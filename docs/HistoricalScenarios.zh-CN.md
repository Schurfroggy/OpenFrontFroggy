# 历史场景玩法更新方向

_OpenFront 私人朋友服的长期玩法构想；当前仅记录方向，不代表已进入开发阶段_

---

## 📋 文档定位

本文记录“基于真实地理地图制作历史或架空场景”的长期更新方向。它的目标不是立即把 OpenFront 改造成复杂的历史模拟器，而是在保留原有扩张、外交与团队对抗核心的前提下，逐步增加更有主题感、可重复游玩的场景模式。

当前开发优先级仍然是把基础玩法打磨稳定。历史场景只应在联机、团队规则、设置约束、成就判定和基础平衡足够可靠后进入实现。

> 📌 **范围说明：** 第一阶段的历史场景是“历史背景下的 OpenFront 对局”，不是严格还原国界、兵力、外交和战线的历史模拟。

## 🎯 设计目标

- 让世界、亚洲、北美洲、南美洲、非洲等真实地图拥有明确的对局主题
- 用固定国家、出生位置和阵营关系替代缺乏叙事的随机组队
- 为单人和朋友联机提供可重复挑战的场景目标
- 复用现有地图国家锚点、AI 国家、团队和成就系统
- 保持场景数据与通用地图数据分离，避免破坏普通沙盒玩法
- 允许后续逐步加入非对称规则、战略目标和预设领土

## 🔍 现有基础

现实地图已经在各自的 `info.json` 中保存国家名称、旗帜和出生坐标。例如[世界地图配置](../map-generator/assets/maps/world/info.json)已经为多个国家标记了大致地理位置。

运行时会把这些坐标转换为 AI 国家的出生锚点，相关逻辑位于：

- [TerrainMapLoader.ts](../src/core/game/TerrainMapLoader.ts)：读取地图清单并处理紧凑地图坐标缩放
- [NationCreation.ts](../src/core/game/NationCreation.ts)：根据地图清单创建 AI 国家
- [NationExecution.ts](../src/core/execution/NationExecution.ts)：在锚点附近寻找有效陆地并完成出生
- [TeamAssignment.ts](../src/core/game/TeamAssignment.ts)：为人类和 AI 国家分配队伍

当前机制已经解决了“某个国家应当大致出现在哪里”，但还没有解决：

- 不同年代使用哪些国家、名称和旗帜
- 哪些国家属于同一历史阵营
- 玩家扮演国家、阵营指挥官，还是额外加入的势力
- 场景专属胜利条件、初始资源和单位限制
- 历史国界、首都、战略城市和事件

普通团队模式会优先考虑人数平衡，而不是历史关系。因此历史场景不能直接使用现有的随机团队分配，也不能通过减少“国家数量”随机抽取参战国。

## ⚙️ 核心玩法优先事项

在开始制作历史场景前，优先完成以下基础工作：

| 优先级 | 方向       | 完成标准                                          |
| ------ | ---------- | ------------------------------------------------- |
| **P0** | 联机稳定性 | 同浏览器多账号、房主开局、断线与重连流程可靠      |
| **P0** | 团队规则   | 人类、国家 AI、部落和不同组队模式的关系清晰可预测 |
| **P0** | 设置约束   | 普通设置简洁；高级设置明确影响成就资格            |
| **P0** | 成就判定   | 单人、多人、团队胜利和参与者奖励规则一致且可验证  |
| **P1** | 基础平衡   | 默认单位、AI 难度、国家数量和获胜条件适合朋友服   |
| **P1** | 界面表达   | 地图、模式、难度和队伍信息在开局前清楚展示        |

这些基础规则也会成为场景模式的底层能力。场景系统不应复制一套独立的战斗逻辑，而应通过受控预设组合现有规则。

## 📚 场景系统构想

### 地图与场景分离

地图只描述地形和通用国家锚点；场景引用地图，并覆盖特定年代的参战国、旗帜、阵营和规则。普通沙盒继续使用现有地图配置，历史场景使用独立文件。

建议的目录形态：

```text
map-generator/assets/maps/world/
├── info.json
└── scenarios/
    ├── cold-war-1962.json
    ├── world-war-1942.json
    └── three-blocs.json
```

这样可以让同一张世界地图同时支持普通沙盒、历史场景和架空场景，不需要复制整张地图。

### 稳定标识

场景中的地图、国家、阵营和场景本身都应使用稳定 `id`。显示名称和翻译文本不能作为数据关联键，因为名称会随语言和时代变化，不同地图也可能存在同名地区。

建议每个场景至少包含：

| 字段            | 用途                                 |
| --------------- | ------------------------------------ |
| `id`            | 场景稳定标识                         |
| `mapId`         | 引用基础地图                         |
| `year`          | 表示历史年代或架空时间               |
| `factions`      | 定义阵营、颜色和成员                 |
| `nations`       | 定义参战国、名称、旗帜、出生点和阵营 |
| `rules`         | 锁定难度、单位、资源和高级设置       |
| `victory`       | 定义领土、时间或目标胜利条件         |
| `achievementId` | 区分普通地图成就和场景成就           |

概念示例：

```json
{
  "id": "cold-war-1962",
  "mapId": "World",
  "year": 1962,
  "factions": [
    {
      "id": "western_bloc",
      "team": "blue",
      "nations": ["united_states", "united_kingdom", "france"]
    },
    {
      "id": "eastern_bloc",
      "team": "red",
      "nations": ["soviet_union", "east_germany"]
    }
  ],
  "rules": {
    "advancedSettings": false,
    "mirv": false
  }
}
```

该结构仅用于表达方向，正式实现前仍需根据现有游戏配置模型确定字段名称和校验方式。

### 玩家角色

历史场景需要明确玩家如何进入战局。可考虑三种方案：

| 方案           | 说明                                   | 评价                         |
| -------------- | -------------------------------------- | ---------------------------- |
| **扮演国家**   | 玩家选择一个场景国家，并取代对应 AI    | 历史感最强，推荐作为长期目标 |
| **阵营指挥官** | 玩家选择阵营，在阵营区域内生成独立势力 | 实现较简单，适合首个版本     |
| **额外势力**   | 玩家照常出生，历史国家仅作为背景 AI    | 改动最小，但叙事感较弱       |

首个可玩版本可以采用“阵营指挥官”，待国家选择、重连和胜负归属稳定后，再支持玩家直接扮演国家。

### 阶段 0：稳定核心玩法

- 完成联机和开局流程的稳定性修复
- 明确团队模式、国家 AI 和部落的规则
- 完善普通设置、高级设置和成就资格提示
- 校验不同难度下的默认规则与成就含金量

### 阶段 1：场景数据框架

- 增加独立场景清单和运行时类型
- 为地图国家增加稳定 `id`
- 支持固定参战国、出生点和阵营
- 在房间中显示场景简介、年份、阵营和锁定规则
- 保留“普通沙盒”作为默认入口

### 阶段 2：首个可玩场景

建议首个场景为“冷战：1962”：

- 使用世界地图
- 固定西方集团和东方集团
- 将未结盟国家设为中立 AI 或第三阵营
- 锁定主要规则，禁止通过高级设置获得场景成就
- 暂时沿用领土占领胜利，不制作历史国界
- 同时支持单人带 AI 队友和朋友联机

这个场景与当前现代国家锚点最接近，也能直接利用红蓝团队视觉，是验证场景框架成本最低的方案。

### 阶段 3：非对称玩法

- 为阵营设置不同初始资源、单位或增益
- 增加首都、战略区域和限时任务
- 增加防守、突围、占领或生存类胜利条件
- 为场景单独设计 AI 行为倾向
- 让不同阵营拥有不同但可平衡的战略选择

### 阶段 4：历史地图状态

- 为国家预设初始领土，而不只是一个出生点
- 保存历史边界、城市和前线数据
- 支持事件、援军、投降和阵营变更
- 为不同年代准备独立国家名称和旗帜

这一阶段属于较大的引擎扩展，应在前面阶段验证玩法价值后再决定是否投入。

## 🌐 候选场景

| 地图       | 首选场景     | 其他候选方向                         |
| ---------- | ------------ | ------------------------------------ |
| **世界**   | 冷战：1962   | 二战：1942、三极世界、架空联盟战争   |
| **亚洲**   | 亚洲冷战     | 太平洋战争、蒙古扩张、三国主题       |
| **北美洲** | 美国独立战争 | 南北战争、英法北美战争、州际架空战争 |
| **南美洲** | 南美独立战争 | 三国同盟战争、大哥伦比亚时代         |
| **非洲**   | 北非战役     | 非洲独立浪潮、殖民争霸、区域联盟战争 |
| **欧洲**   | 拿破仑战争   | 一战、二战、冷战欧洲                 |

历史题材应尽量基于可靠资料核对国家、旗帜和阵营。若地图精度或玩法规则无法支持严格还原，应在界面中使用“历史启发”或“架空场景”表述，避免把游戏简化结果当作历史事实。

## 🏆 成就与设置规则

普通地图难度成就和历史场景成就应分开存储。建议成就键至少包含：

```text
用户名 + 地图 ID + 场景 ID + 难度 + 模式
```

建议采用以下资格规则：

- 使用场景规定的标准配置完成对局才能获得场景成就
- 启用高级设置后不得获得场景成就
- 团队模式胜利时，符合参与条件的胜方玩家共同获得成就
- 中途加入、观战、掉线和重新连接的资格需要统一规则
- 场景平衡调整后，可通过成就版本号区分旧规则与新规则

这样可以避免场景预设和普通沙盒使用不同规则，却错误地授予同一枚地图难度徽章。

## ⚠️ 明确不在首版范围内

- 精确还原历史国界和每支军队的位置
- 完整外交、贸易、意识形态或科技树系统
- 通过事件脚本强制复刻历史结果
- 为每个年代重制独立地形地图
- 追求严肃历史模拟级别的数值精度
- 一次性制作大量场景

首版只验证一个问题：固定国家、地理位置、阵营和规则后，是否能让 OpenFront 的朋友对局更有主题、更有策略差异，也更值得重复游玩。

## ✍️ 后续决策清单

进入实现前需要依次确认：

- [ ] 核心联机和开局流程已经稳定
- [ ] 团队与成就规则已经定稿
- [ ] 玩家在场景中扮演国家还是阵营指挥官
- [ ] 中立国家属于独立阵营还是无队伍 AI
- [ ] 首个场景的固定参战国和阵营名单
- [ ] 场景规则是否允许房主调整
- [ ] 场景成就的数据格式和版本策略
- [ ] 场景数据由地图作者还是独立场景文件维护
- [ ] 历史题材的名称、旗帜和说明如何校验
