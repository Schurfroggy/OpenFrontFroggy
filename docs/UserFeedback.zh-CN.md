# 对局反馈

此功能用于自托管部署，复用现有登录会话、管理员权限和 `SELF_HOSTED_DB_PATH` 指定的 SQLite 数据库（默认 `data/self-hosted.sqlite`）。无需新增外部服务；首次使用时自动创建 `user_feedback` 表。备份、升级时应保留数据库文件。

已出生的玩家在胜利或失败结算时看到反馈卡片；桌面端位于统计右侧，窄屏位于下方。观战者和回放不显示。评价、问题标签、文字三者至少填写一项，文字上限 500 字。选择卡顿或连接问题后可选择发生阶段。关闭反馈不影响退出或继续观战。页面存续期间保留最近对局的草稿，刷新页面不保留草稿。

默认附带诊断摘要，可取消。摘要在反馈卡片首次出现时冻结，最多保留最近五分钟的十个已完成窗口和一个当前窗口，包含帧间隔、worker 报告的模拟耗时、回合接收间隔、WebSocket RTT 和本页面会话的重连次数，以及浏览器和视口大小。数据采样不依赖 Grafana 开启；未点击提交不会向反馈接口上传。这里的 worker 耗时沿用现有计量范围，RTT 包含客户端主线程等待，均不能单独证明服务器或网络故障。

基础对局信息由浏览器附带：地图、尺寸、模式、难度、AI 配置、时长、结果和版本。服务端绑定提交账号并记录接收时间；对局上下文及诊断是客户端报告的数据，不作为服务器验证过的事实。请求不附带聊天、截图、完整日志或认证令牌。登录认证通过现有 HttpOnly 会话 cookie 处理。

只有写入成功才显示成功提示。失败保留填写内容，允许重试；请求使用提交 UUID 并按账号和对局去重，同一账号同一局只保留首条成功反馈。每个账号每分钟最多十次请求。反馈通过 HTTP 提交，不依赖游戏 WebSocket 连接仍存活。

管理员登录后在现有管理面板的“用户反馈”区查看，每页二十条，按状态筛选、按地图/模式/版本/分类代码/用户名/文字搜索，展开查看基础信息和可选诊断摘要，并保存处理状态及内部备注。列表时间转换为管理员浏览器的本地时间。所有读取与处理接口均在服务端检查管理员身份。

接口：

- `POST /api/self-hosted/feedback`：登录账号提交，校验输入并返回反馈编号。
- `GET /api/self-hosted/admin/feedback?page=0&status=pending&q=China`：管理员分页搜索。
- `PATCH /api/self-hosted/admin/feedback/:id`：管理员提交 `status` 和 `note`，处理状态为 `pending`、`investigating`、`resolved` 或 `archived`。

本版未提供游戏中菜单入口、附件上传、管理员主动回复或自动删除历史反馈。反馈保存在现有数据库中，具有该数据库运维权限的人员也可访问。
